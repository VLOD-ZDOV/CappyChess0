# ♛ Capablanca Chess Zero

*[English version](README.md)*

**Движок в духе AlphaZero, обученный целиком на игре с самим собой** — без
человеческих партий, без дебютных книг, без написанной руками оценки. Сеть
доходит до всего сама.

Проект состоит из трёх частей:

| Часть | На чём | Зачем |
|------|-------|------|
| **Движок** | Rust + PyO3 | генерация ходов, правила, кирпичи MCTS |
| **Обучение** | Python + PyTorch | самоигра, буфер повторов, обучение сети |
| **Анализ** | PyQt5 + onnxruntime | GUI в духе Nibbler для разбора партий |

## ⚡ Быстрый старт

По шагам, по порядку. Команды даны для **Linux/macOS** и **Windows** — выбери
свою колонку и держись её. Всё запускается из корня репозитория, если в шаге не
сказано иначе.

### 0. Правила игры за тридцать секунд

Доска **10×8** — вертикали `a`…`j`, горизонтали `1`…`8`. Две фигуры, которых нет
в обычных шахматах:

| | ходит как |
|---|---|
| **A** — архиепископ | слон **+** конь |
| **C** — канцлер | ладья **+** конь |

Начальный ряд: `R N A B Q K B C N R`, то есть король стоит на **f1** (у чёрных
на `f8`).

**Рокировка двигает короля на три клетки, а не на две:**

| | король | ладья | должно быть пусто |
|---|---|---|---|
| короткая | `f1` → `i1` | `j1` → `h1` | `g1 h1 i1` |
| длинная | `f1` → `c1` | `a1` → `d1` | `b1 c1 d1 e1` |

Записывается как ход короля: `f1i1` или `f1c1`. Ходы в формате UCI (`e2e4`), у
превращения добавляется буква — обычные `q r b n` плюс **`a`** архиепископ и
**`c`** канцлер (`e7e8a`).

Экспортируй из *снимка*, а не из `latest.pth`, который прямо сейчас
перезаписывает идущее обучение.

**В терминале** — без GUI и без дисплея:

```
cd python_src
python play_cli.py ../weights.pth --sims 800 --side white
```

`moves` печатает легальные ходы, `quit` выходит. Можно по одному ходу за вызов,
храня партию в файле состояния (удобно по ssh или чтобы скриптом натравить

```
python play_cli.py ../weights.pth --new --side white --move e2e4
python play_cli.py ../weights.pth --move d2d4
```

сети**, то есть `Q=+0.9` значит «сеть считает, что выигрывает она».

### 6. Обучать

```
cd python_src
python -u train.py \
    --channels 256 --res-blocks 10 \
    --transformer-blocks 10 --transformer-heads 8 --ffn-mult 4 \
    --swiglu --qk-norm --rmsnorm --no-qkv-bias \
    --restricted-policy --abs-pos-embed --wide-value --no-future \
    --games 384 --mcts-batch 128 --mcts-parallel-sims 8 \
    --simulations 400 --fast-simulations 100 \
    --batch-size 512 --train-steps 40 \
    --buffer-max 1000000 --lr 2e-4 \
    --value-q-weight 0.25 --no-value-balance \
    --save-every 10 --latest-dir /tmp --checkpoint-dir checkpoints
```

Три флага отсюда — это то, на чём шёл самый сильный прогон, и каждый из них
измерен отдельно:

- **`--value-q-weight 0.25`** подмешивает в цель для value собственную оценку
  поиска вместо одного лишь результата партии. Иначе все ~28 позиций партии
  получают одну и ту же метку, и сеть её просто заучивает.
- **`--no-value-balance`** берёт из буфера равномерно, как делает Leela. По
  умолчанию батч выравнивается на треть побед, треть ничьих, треть поражений — а
  это показывает ничейную позицию раз десять за время жизни буфера против
  примерно двух раз для решённой и учит голову WDL, что ничьих 33%, когда в
  реальности их около 10%.
- **`--latest-dir`** держит `latest.pth` в каталоге в оперативной памяти. Это
  ~440 МБ, переписываемые каждую итерацию, — основная запись на диск за весь
  прогон. На диск по-прежнему идут нумерованные архивы и копия по Ctrl+C или
  `kill`, так что остановленный прогон продолжается ровно с того же места.

На Windows убери обратные слэши и вытяни в одну строку либо используй обратную
кавычку `` ` `` для переноса.

Три настройки ломают обучение *молча* — без падения, просто сеть выходит слабее:

- **`--mcts-parallel-sims`** — сколько листьев уходит на карту за один вызов.
  `ceil(--simulations / --mcts-parallel-sims)` — это число *последовательных*
  раундов PUCT. Ниже примерно двенадцати раундов virtual loss размазывает визиты
  по корню ровным слоем, и сохранённая цель для политики вырождается в
  равномерную. **Держи это отношение не ниже 12.**
- **`--train-steps` против `--games`** — отношение
  `train_steps × batch_size / новых позиций за итерацию` показывает, сколько раз
  градиент проходит по каждой позиции. Целься в **3–4**, как держит Leela; при 38
  сеть заучивает буфер вместо того чтобы учиться шахматам, и слабеет, пока лосс
  красиво падает к нулю. За отношением надо следить на длинном прогоне: сеть
  усиливается, партии укорачиваются, те же `--games` дают меньше позиций, и
  отношение ползёт вверх — подними `--games`, чтобы вернуть его на место.
- **Флаги архитектуры при продолжении обязаны совпадать дословно.** Сеть
  собирается из флагов, а веса грузятся с `strict=False`, поэтому расхождение не
  падает с ошибкой — оно молча теряет тензоры.

Долгие прогоны запускай отцепленными, а не внутри панели терминального
мультиплексора: умрёт его сервер — утащит прогон с собой.

```bash
setsid nohup python -u train.py … >> train.log 2>&1 < /dev/null &
tail -f train.log
```

### 7. Убедиться, что сеть правда учится

Лосс обучения об этом не скажет — *падающий* лосс прекрасно уживается с сетью,
которая слабеет. Три команды, от самой дешёвой:

```
python overfit_check.py checkpoints/buffer.npz checkpoints/model_iter*.pth
```

Прогоняет сеть по самым старым и самым свежим позициям буфера. По старым прошло
много проходов градиента, по свежим почти ни одного, поэтому **разрыв в 2 раза и
больше значит, что сеть заучивает** буфер, а не обобщает — и её `value_loss`
меряет память. Занимает секунды.

```
python policy_health.py checkpoints/model_iter*.pth
```

Печатает `max(p)·n_legal` — насколько лучший ход острее равномерного. `1.0` —
равномерно, `1.04` — случайно инициализированная голова. Ловит расплющенную
голову политики, которая со стороны выглядит как плато лосса. Заметь: *острее не
значит сильнее* — в этом проекте острота росла, а сила падала.

```
python eval.py old.pth new.pth --games 200 --simulations 200 \
       --mcts-parallel-sims 8
```

Личная встреча — **единственная надёжная мера силы**. Счёт против случайного
соперника ранжирует сети в *обратном* порядке: более сильная сеть чаще делает с
ним ничью, потому что не дожимает, а не потому что играет хуже.

Для абсолютной отметки есть лестница Fairy-Stockfish по `UCI_Elo`
(`fsf_ladder.py`). Не используй `--fsf-nodes`: лимит по узлам почти не ослабляет
движок, и все сети проекта показывали против него ровно 0% независимо от силы.

## ✨ Главное

- **Честный цикл AlphaZero**: самоигра → буфер повторов → обучение → сеть сильнее.
- **Гибридная сеть**: свёрточный ResNet со Squeeze-Excitation, поверх него блоки
  Transformer с относительным позиционным смещением. Внимание идёт через
  сращённый `scaled_dot_product_attention` из PyTorch — он сам выбирает
  FlashAttention или экономный по памяти вариант.
- **Четыре головы**: политика, оценка (WDL), moves-left и «будущий ход», нужный
  только при обучении.
- **MCTS со слиянием транспозиций** (в GUI): позиции, достигнутые разным порядком
  ходов, сливаются в один узел поиска — Lc0 этого сознательно не делает.
- **Переиспользование дерева между ходами**: после сыгранного хода нужное
  поддерево становится новым корнем, статистика переезжает вместе с ним.
- **Курс обучения против Fairy-Stockfish**: учитель, подстраивающийся под
  текущую силу сети.
- **Самодостаточный GUI**: один файл `.onnx` плюс движок на Rust. PyTorch на
  инференсе не нужен. Ускорение на карте — через `onnxruntime-gpu` (среда
  выполнения CUDA лежит внутри самого пакета).

## 🔄 Как это работает

Одна итерация обучения — замкнутый круг:

```
        ┌─────────────────────────────────────────────┐
        │                                             │
   партии самоигры          обучение на выборке       │
   (батчевый MCTS +   ─────► мини-батчей       ──────►│ новые веса
    текущая сеть)           (policy + value +         │
        ▲                    MLH + future)            │
        │                                             │
        └────────── буфер повторов (FIFO) ◄───────────┘
```

1. **Самоигра.** Текущая сеть играет большую пачку партий сама с собой. Каждый
   ход выбирается поиском MCTS, который ведут политика и оценка сети. Счётчики
   визитов становятся *целью для политики*, результат партии (смешанный с
   оценками поиска) — *целью для value*.
2. **Буфер повторов.** Позиции последних итераций лежат в FIFO-буфере. По
   умолчанию выборка выравнивает победы, ничьи и поражения по трети;
   `--no-value-balance` берёт равномерно, как Leela.
3. **Обучение.** Сеть учится предсказывать политику поиска, исход партии, число
   оставшихся полуходов и будущий ход — мультизадачный лосс.
4. **Повтор.** Улучшенная сеть идёт в следующий круг самоигры. Сила
   накапливается от итерации к итерации.

По желанию часть партий играется против **Fairy-Stockfish** как внешнего учителя
(см. «курс обучения» ниже).

## 🧠 Архитектура сети — `CapablancaNet`

### Кодировка входа — 139 плоскостей

Доска подаётся тензором `(139, 8, 10)`, **канонически перевёрнутым** так, чтобы
сторона, которая ходит, всегда «играла вверх». Благодаря этому сети нужно выучить
только одну точку зрения.

```
139 плоскостей = 8 позиций истории × 17  +  3 мета-плоскости

на каждый слот истории (новейший первым):
  8  наши фигуры   (P N B R Q A C K)
  8  чужие фигуры
  1  флаг повторения
мета:
  1  права рокировки (4 зоны в одной плоскости)
  1  счётчик полуходов / 100
  1  плоскость из единиц (подсказка свёртке, где край доски)
```

Плоскости истории дают сети чувство движения и позволяют видеть повторения.

### Ствол

```
вход  (139, 8, 10)
   │
   ▼  Conv 3×3 → GroupNorm → Mish              ── входная башня
   │
   ▼  N × ResBlock                             ── остаточная башня
   │     Conv→GN→Mish → Conv→GN
   │     затвор Squeeze-Excitation (масштаб + сдвиг)
   │     + остаток → Mish
   │
   ▼  разворот в 80 токенов (по одному на клетку)
   │
   ▼  K × TransformerBlock                     ── башня внимания
   │     Pre-LN → MHA(+RPB через SDPA) → +остаток
   │     Pre-LN → FFN(Mish) → +остаток
   │
   ▼  свёртка обратно в (C, 8, 10) → головы
```

Осознанные решения:

- **GroupNorm, а не BatchNorm.** У GroupNorm нет накопленной статистики, поэтому
  он ведёт себя одинаково при батче 1 (инференс листа в MCTS) и не уплывает,
  когда распределение данных меняется по ходу обучения.
- **Активация Mish** (`x · tanh(softplus(x))`) — гладкая и самозатворная, в
  глубоких стопках устойчивее ReLU.
- **Squeeze-Excitation** в каждом остаточном блоке. Ветка SE выдаёт и
  **масштаб, и сдвиг** по каналам, позволяя сети перевзвешивать карты признаков
  по глобальному контексту позиции.
- **Transformer с относительным позиционным смещением (RPB).** 80 клеток
  становятся токенами, и самовнимание связывает любые две клетки за один шаг.
  Смещение зависит только от *разности* `(Δгоризонталь, Δвертикаль)` между
  клетками: прыжок коня — это одно и то же смещение в любом месте доски, так что
  геометрию сеть получает с самого начала. RPB стоит ~2.3 тысячи параметров на
  блок — на три порядка дешевле, чем подходы вроде Smolgen.
- **`scaled_dot_product_attention`** вместо написанных руками `matmul + softmax`.
  PyTorch сам выбирает лучший вариант (FlashAttention, экономный по памяти или
  обычный) по форме тензоров и железу. RPB заезжает туда как добавочная
  `attn_mask`.

### Головы

| Голова | Выход | Зачем |
|------|--------|---------|
| **Политика** | 7000 логитов | вероятности ходов — приоритет для MCTS |
| **Оценка (WDL)** | 3 логита → softmax | `P(выигрыш)`, `P(ничья)`, `P(поражение)`; скалярная оценка `Q = P(выигрыш) − P(поражение)` |
| **Moves-Left** | 1 скаляр (сигмоида) | сколько полуходов осталось — даёт MCTS предпочитать быстрые выигрыши и медленные поражения |
| **Будущий ход** | 7000 логитов | предсказывает *наш* ход через два полухода; **только при обучении** — вспомогательная задача, толкающая ствол к признакам, пригодным для планирования |

Голова политики и голова будущего хода проходят через бутылочное горлышко `1×1`
в 32 канала перед последним линейным слоем. Ширина выбрана не случайно: более
узкое горлышко делает выход на 7000 классов физически низкоранговым и притупляет
тактическую остроту.

Голова WDL (вместо одного скаляра через `tanh`) даёт более чистые градиенты: сеть
явно отделяет «острую обоюдоострую» позицию от «мёртвой ничьей» и учится под
перекрёстной энтропией, а не под среднеквадратичной ошибкой.

При инициализации выходные слои голов ослаблены (`gain = 0.01`), поэтому свежая
сеть стартует с почти равномерных приоритетов и плоского WDL `[⅓, ⅓, ⅓]` — без
беспочвенных предпочтений до того, как она хоть чему-то научилась.

Типовая конфигурация: **256 каналов × 15 остаточных блоков + 4 блока
Transformer** (8 голов внимания).

## 🔍 Внутри поиска (MCTS)

- **Отбор по PUCT** с параметрами, взятыми у Lc0 (`c_puct = 1.745`,
  логарифмический рост `c_puct`, `FPU = 0.330`, virtual loss).
- **Virtual loss как настоящая сила расталкивания.** Каждый лист, ушедший на
  расчёт, помечает своих предков штрафом `-1` в числителе Q. Поэтому
  параллельные отборы разбегаются по разным ходам вместо того, чтобы схлопнуться
  на текущем лучшем. Штраф снимается ровно один раз — когда возвращается оценка
  сети, и никогда внутри `backup`.
- **Узлы без доски** — узел занимает ~60 байт, позиция восстанавливается
  проигрыванием ходов, и дерево остаётся дружелюбным к кэшу процессора.
- **Батчевый поиск** — все партии итерации ищутся вместе, чтобы карта получала
  один крупный батч.
- **Выравнивание батча по бакетам** для `torch.compile(mode='reduce-overhead')`.
  Батч дополняется до ближайшей степени двойки, так что до скомпилированного
  графа доходит всего десяток разных форм — CUDA Graphs держатся вместо
  перекомпиляции на каждом шаге.
- **Переиспользование дерева** — после сыгранного хода нужное поддерево
  становится новым корнем, визиты не выбрасываются.
- **Слияние транспозиций** (в GUI) — статистика поиска живёт на узле *позиции*,
  приоритеты на *рёбрах*, поэтому разные порядки ходов, ведущие в одну позицию,
  делят один узел и складывают визиты.
- **Ранний выход по KLD** — поиск останавливается, когда распределение визитов
  перестало меняться (как у Lc0).
- **Contempt** (по желанию) — Q сдвигается на `contempt * вероятность ничьей`.
  Положительный contempt заставляет избегать ничьих (полезно против слабого
  внешнего соперника), отрицательный — принимать их.
- **Переключатель шума Дирихле.** В самоигре он включён (исследование), в
  матчах, партиях против FSF и против отстающей копии — выключен, чтобы
  измерение показывало настоящий выбор сети.

## 🎛 Возможности GUI

GUI для анализа (`python_src/gui.py`) грузит один граф `.onnx` и считает через
`onnxruntime`. PyTorch на инференсе не нужен.

- **Отрисовка стрелок в два прохода** — как у Nibbler. Сначала все стрелки,
  потом поверх подписи. Толщина и прозрачность зависят от места в рейтинге, так
  что лучший ход виден сразу. Подписи прижаты к клетке назначения, а не висят на
  древке, и не наезжают друг на друга на пересекающихся стрелках.
- **Показ мата** в боковой шкале. Когда Q лучшего хода близко к ±1, а
  вероятность ничьей мала, шкала показывает `M<n>` / `-M<n>` с точки зрения
  белых вместо процентов.
- **Переиспользование дерева между ходами.** Таблица транспозиций живёт между
  поисками, и новый поиск в уже виденной позиции подхватывает накопленную
  статистику.
- **Умная обрезка** вместо очистки. Когда таблица переваливает за 500 000 узлов,
  остаётся только поддерево, достижимое из текущей позиции. Остальное
  выбрасывается — ничего из того, что пригодилось бы следующему поиску, не
  теряется.
- **Ограниченный кэш сети** (по умолчанию ~150 000 записей, потолок ~4 ГБ
  оперативной памяти). Долгие сессии больше не раздувают память.
- **Ползунки c_puct и contempt** на панели. Для анализа подними c_puct до
  2.5–3.0, чтобы поиск смотрел шире; положительный contempt уводит от ничьих.
- **Живой главный вариант** на каждый ход (10 полуходов) в информационном окне.

## 🧩 Что взято у Leela Chess Zero

[Leela Chess Zero](https://lczero.org/) — открытый шахматный проект в духе
AlphaZero. Несколько его выверенных сообществом идей используются и здесь:

- **Параметры PUCT** прямо из `params.cc` в Lc0 — подобраны на миллионах
  партий, а не угаданы.
- **Голова WDL** — предсказание тройки «выигрыш / ничья / поражение» вместо
  одного числа.
- **Moves-Left Head** — чтобы доводить выигранные позиции, а не шаркать.
- **Головы будущего хода** — вспомогательный сигнал планирования, из сетей BT4.
- **Ствол на Transformer с относительным позиционным кодированием** — в духе
  сетей BT3+ (RPB вместо Smolgen).
- **Активация Mish** — принята в Lc0 с BT3.
- **Playout-cap randomization** — большинство ходов ищется дёшево и неглубоко, а
  в буфер обучения попадают только позиции полного поиска.
- **Ранний выход по KLD** — поиск прекращается, когда распределение визитов
  устаканилось.
- **Веса EMA** — самоигра идёт на экспоненциально усреднённых весах, обратная
  связь получается спокойнее.
- **Распространение доказанных границ** (StickyEndgames) — доказанные терминалы
  двигают отбор сдвигом счёта на ±100, и поиск держится за известный исход.

## 🎛 Что взято у Nibbler

[Nibbler](https://github.com/rooklift/nibbler) — любимый многими GUI для анализа
под Lc0. Он намертво привязан к доске 8×8 и протоколу UCI, так что нашу сеть в
него не воткнуть, — но его идеи сформировали здешний GUI:

- **окно ходов с рейтингом**, где на каждый ход показаны `N` (визиты), `P`
  (приоритет сети), `Q` (оценка) и полоска WDL;
- **живой фоновый анализ**, который обновляется непрерывно;
- **шкала оценки** и **график процента выигрыша по партии**;
- **цветные стрелки лучших ходов** с процентом внутри;
- **снимки анализа** — перемотка по истории показывает сохранённый результат, а
  не запускает поиск заново.

Сверх идей Nibbler здешний GUI добавляет своё: слияние транспозиций в дереве
поиска, переиспользование дерева между ходами (визиты накапливаются) и главный
вариант для каждого хода в рейтинге.

## 🚀 Запуск из исходников

Это путь «собери и запусти сам» — поставить зависимости и звать скрипты напрямую.
(Как собрать бинарник в один клик — ниже, в разделе про упаковку.)

Наборов зависимостей два: **GUI** обходится лёгким стеком инференса, **обучению**
дополнительно нужен PyTorch.

### Что нужно

- Python 3.10+
- Тулчейн Rust (`rustup`) — чтобы собрать движок
- Для расчёта на карте: свежий драйвер NVIDIA (сама среда CUDA лежит внутри
  пакета `onnxruntime-gpu`, ставить CUDA Toolkit не надо)

### 1. Собрать движок на Rust

Движок компилируется в модуль Python с именем `capablanca_engine`. Из каталога
`rust_engine/`:

```bash
pip install maturin
PYO3_USE_ABI3_FORWARD_COMPATIBILITY=1 maturin develop --release
```

### 2. Поставить зависимости Python

Только GUI и инференс:

```bash
pip install -r python_src/requirements.txt
```

Это `numpy`, `PyQt5` и `onnxruntime-gpu` — на машине без видеокарты NVIDIA
замени `onnxruntime-gpu` на `onnxruntime`.

Обучению дополнительно нужен PyTorch — ставь сборку под свою CUDA:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cu121
```

### 3. Обучить сеть *(по желанию, нужен PyTorch)*

С нуля, на самоигре:

```bash
python train.py --channels 256 --res-blocks 10 \
                --transformer-blocks 10 --transformer-heads 8 --ffn-mult 4 \
                --restricted-policy --abs-pos-embed --wide-value --no-future \
                --simulations 600 --games 128 \
                --mcts-batch 128 --mcts-parallel-sims 8 \
                --kld-threshold 8e-3 \
                --compile-inference default
```

С учителем Fairy-Stockfish (курс обучения) — сила соперника растёт, когда процент
побед высок, и падает, когда он падает, так что сеть всё время играет на пределе
своих возможностей:

```bash
python train.py --channels 256 --res-blocks 15 \
                --fsf-path ./fairy-stockfish-largeboard_x86-64-bmi2 \
                --curriculum --fsf-nodes-start 1 --curriculum-sp-ratio 0.5 \
                --contempt 0.2
```

`--contempt 0.2` полезен **только при игре против внешнего соперника** (FSF). В
чистой самоигре обе стороны применяют contempt симметрично, и обучающий сигнал
получает структурный сдвиг — для самоигры держи contempt на нуле.

### 4. Экспортировать сеть в ONNX *(нужен PyTorch)*

GUI работает с графом `.onnx`, а не с чекпоинтом `.pth`. Экспортёр идёт через
путь PyTorch, которому нужны ещё `onnx` и `onnxscript`:

```bash
pip install onnx onnxscript
python export_onnx.py checkpoints_big/latest.pth capablanca.onnx
```

Это запекает архитектуру **и** веса в один двоичный файл и заранее применяет
softmax и свёртку WDL — поэтому сам GUI не тащит за собой PyTorch. Экспортёр
сначала пробует современный путь через dynamo и молча откатывается на старый
экспортёр TorchScript, если понадобится (см. `KNOWN_QUIRKS.md`).

### 5. Запустить GUI анализа

```bash
python gui.py
```

Если рядом с `gui.py` лежит `capablanca.onnx`, он загрузится сам; иначе выбери
файл через «Загрузить сеть» — этот диалог принимает и чекпоинт обучения (`.pth`)
и конвертирует его на лету. Расчёт на карте включается сам при наличии NVIDIA (в
строке состояния видно `GPU · CUDA`), с тихим откатом на процессор.

### Турнир между двумя чекпоинтами *(нужен PyTorch)*

```bash
python eval.py <weights_A.pth> <weights_B.pth> --games 200 \
       --simulations 200 --mcts-parallel-sims 8
```

`eval.py` восстанавливает **всю** архитектуру из чекпоинта (каналы, остаточные
блоки, блоки Transformer, головы, переключатели mlh/future), поэтому сравнение
двух чекпоинтов разной формы работает правильно.

## 📦 Сборка отдельного бинарника

Чтобы раздавать GUI, не заставляя людей ставить Python и зависимости:

1. Экспортируй итоговую сеть через `export_onnx.py` (один `capablanca.onnx`).
2. Собери движок на Rust под целевую систему (`.so` на Linux, `.pyd` на
   Windows).
3. Упакуй **PyInstaller**:

   ```bash
   pip install pyinstaller
   cd python_src
   pyinstaller --noconfirm --clean --name capablanca-gui \
       --paths . \
       --hidden-import onnx_engine \
       --collect-all onnxruntime \
       --collect-all capablanca_engine \
       --exclude-module torch --exclude-module matplotlib \
       --exclude-module scipy --exclude-module pandas \
       --exclude-module tensorrt --exclude-module tensorrt_libs \
       --exclude-module triton --exclude-module cupy \
       gui.py
   ```

   Исключения важны: без них в сборку заезжает TensorRT и раздувает её до
   нескольких гигабайт, хотя GUI им не пользуется.

   **Собрать `.exe` под Windows можно и из Linux, через Wine.** Сам PyInstaller
   кросс-компилировать не умеет, но ничто не мешает запустить под Wine
   настоящий виндовый Python и собрать им. Движок на Rust кросс-компилируется
   обычным `cargo build --target x86_64-pc-windows-gnu` (нужна возможность
   `generate-import-lib` у pyo3 и переменная `PYO3_CROSS_PYTHON_VERSION`), а
   полученный `.dll` переименовывается в `capablanca_engine.pyd` и добавляется
   через `--add-binary`. Учти, что pip внутри Wine обычно не видит сеть: колёса
   качаются хозяйским pip с `--platform win_amd64` и ставятся с
   `--no-index --find-links`, причём зависимости с пометкой
   `sys_platform == "win32"` (`pefile`, `pywin32-ctypes`) надо перечислить руками.

4. Положи `capablanca.onnx` рядом с полученным исполняемым файлом — GUI
   подхватит его сам.

`onnxruntime-gpu` несёт в себе среду выполнения CUDA, так что сборка считает на
карте на любой машине с драйвером NVIDIA — без PyTorch и без CUDA Toolkit.
Сборка отдельная под каждую систему, кросс-компиляции нет: под Linux собирай на
Linux, под Windows на Windows.
